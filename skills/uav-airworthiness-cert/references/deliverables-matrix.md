# Deliverables matrix and gap analysis

directions: forward to build the checklist for a stage, backward to find which
requirement a document satisfies — that is what keeps a document from being
rewritten twice for two different clauses.

## Gap analysis procedure

Run this before drafting anything, and again before submitting.

1. **List what exists.** Enumerate the files actually on disk with an absolute
   path and a version. Do not list what you remember writing.
2. **List what is required** for the stage being submitted, from the tables above.
3. **Match them.** A document can satisfy several rows — record the mapping; that
   mapping is the reuse register.
4. **Classify each gap:** 缺失（does not exist） / 不完整（exists, missing required
   fields from [contracts.md](contracts.md)） / 未生效（draft, not approved） /
   内容错误（fails a verifier).
5. **Report** as a table: 交付物 | 依据 | 状态 | 现有文件（绝对路径） | 缺口 | 建议动作.
6. **Do not draft a new document when an existing one only needs the missing
   fields filled.** Rewriting is the most common waste in this workflow.

times; that is the point.

the requirement. If one exists but is incomplete, extend it rather than starting
a parallel document.
