# CAAC-UAV适航审定skill

> 仓库地址：<https://github.com/jojopai/CAAC-UAV-skill>（仓库名 `CAAC-UAV-skill`，中文名作为项目名）

面向 Codex 的**民用无人驾驶航空器适航取证**技能集。它把中国民航局现行的无人驾驶航空器适航审定法规，变成模型可执行、可机器核对的工作方法：先判定类别与路线，再建符合性与体系，最后过颁证门并维持证件有效。

> **声明**：本仓库不是官方文件，不能替代民航局的审查结论。所有条款、时限与数值均来源于民航局公开发布的文件；如有出入，以官方发布版本为准。原始文件清单与下载地址见 [docs/sources.md](docs/sources.md)，本仓库不转载原文。

## 为什么需要它

无人机的适航取证是一条跨年的长流程，涉及三条并行工作线（型号合格审定、设计机构许可、生产机构许可）和大量法定时限。实务中真正拖慢进度的不是"不知道规则"，而是三件事：

1. **条款引错** —— 凭记忆引用条款号，或引用了未生效、已废止的版本；
2. **要求漏项** —— 只满足"记得住"的要求，而不是文件里全部适用的要求；
3. **重复造轮** —— 同一份证据为不同条款重写多遍，或整改后未做回归检查。

这套技能针对的正是这三点：条款引用必须**回原文机器核对**，要求必须**从原文提取后逐条处置**，证据必须**登记复用**。

## 包含的三个技能

按取证生命周期划分，三个阶段各一个技能；共享底座放在阶段一，另两个以路径调用，不复制。

| 技能 | 阶段 | 做什么 |
| --- | --- | --- |
| [uav-airworthiness-cert](skills/uav-airworthiness-cert/) | ① 判定与准入 | 类别与路线判定、申请资格与时机、受理、过渡期；**并持有共享底座**（语料、法规地图、产物契约、三个校验脚本、状态台账） |
| [uav-cert-compliance](skills/uav-cert-compliance/) | ② 符合性与体系 | 审定基础、符合性方法 MC0~MC9、设计保证系统 DOA、生产质量系统 POA、两本手册、不符合项整改 |
| [uav-cert-sustain](skills/uav-cert-sustain/) | ③ 颁证与维持 | 颁证前置检查、标准与特殊适航证、特许飞行证、逐架机放行、证后更改、监督、报告义务、证件有效期 |

## 安装

### 方式一：用 Codex 的 skill-installer

在 Codex 中说：

```
从 jojopai/CAAC-UAV-skill 安装技能，路径 skills/uav-airworthiness-cert、skills/uav-cert-compliance、skills/uav-cert-sustain
```

### 方式二：手动复制

```bash
git clone https://github.com/jojopai/CAAC-UAV-skill.git
mkdir -p ~/.agents/skills
cp -R CAAC-UAV-skill/skills/* ~/.agents/skills/
```

安装后技能在**下一轮对话**即可被自动发现。阶段二、三需要阶段一存在，因为校验脚本与法规地图放在那里。

## 首次使用

技能不附带法规原文（避免转载），第一步是从民航局官网下载原文并建立语料：

```bash
# 1. 按 docs/sources.md 的清单，把法规 PDF 下载到某个目录
# 2. 建立可检索语料（一份文本 + index.json）
python3 ~/.agents/skills/uav-airworthiness-cert/scripts/build_corpus.py \
  --src "<你存放法规 PDF 的目录>" \
  --out "<你的项目目录>/.uav-cert-corpus"
# 3. 查看输出中标记为 needs OCR 的条目：扫描件没有文字层，需渲染后人工阅读
```

之后所有条款工作都基于这份语料：引用必须能核到，核不到就标出来，而不是放过。

## 四个自带脚本

| 脚本 | 作用 |
| --- | --- |
| `build_corpus.py` | 把 PDF（含 .rar 内文件）提取成可检索文本与索引，并标记需 OCR 的文件 |
| `verify_citations.py` | 检查文档中的每条条款引用是否存在于语料；支持显式豁免标记 `citation-check: ignore`，并打印被豁免的行 |
| `check_consistency.py` | 检查同一时限或数值是否在它应当出现的每份文件中都出现 |
| `extract_requirements.py` | 从语料提取全部强制语句，生成带条款号的要求清单，用于逐条处置适用性 |

四个脚本都做了正反两向测试；反向测试（人为写入不存在的条款）是必需的，否则无法确认检查真的有效。

## 设计要点

- **类别先行**：最大起飞重量、是否载人、是否融合飞行、是否在人口密集区域上方飞行，四项未定则不进入后续流程。这四项直接决定审查依据、证件类型与工作量。
- **要求来自原文**：适用要求由脚本从语料提取后逐条处置（适用 / 不适用加理由 / 由专用条件确定），空处置视为未关闭事项。
- **复核在定稿前**：修复后必须单独做回归检查；关闭一条同时新开两条按失败轮次处理。
- **时限是法定值**：循环边界由法定时限决定，不由轮数决定。
- **不编造**：缺信息写"待确认"，宁可暴露空白，不给自信的猜测。
